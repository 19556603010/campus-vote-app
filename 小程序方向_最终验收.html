《项目实训（一）》小程序方向 — 最终验收

AI 编程 · 微信小程序 · 云开发

️ 最终验收说明
1. 本次课为最终验收，课程结束后项目不再计入学分，后续优化由学生自行完成。
2. 前两次课未完成的同学，优先补齐前两次课要求，再推进本次课内容。
3. 开发工具统一使用 Trae IDE 进行 AI 辅助编程，微信开发者工具仅用于预览和上传。
4. 每人独立完成一个微信小程序，通过体验版提交验收。

前两次课要求回顾（未完成者必须补齐）

第一次课要求（环境 + 初始化）

  • 微信小程序账号注册成功，拿到 AppID
  • 微信开发者工具能正常创建项目并运行
  • 云开发环境开通成功（显示"免费开发环境"）
  • Trae 能打开项目目录，修改代码后微信工具自动刷新
  • GitHub 仓库已创建，项目代码已 push
  • 已确定个人项目方向（游戏 / 工具 / 社交互动）
  • 至少完成 1 个可运行的页面（有基本界面，能显示内容）

第二次课要求（核心功能 + 云数据库）

  • 游戏方向：游戏主循环跑通、计分系统、分数写入云数据库、≥2 个页面
  • 工具方向：添加功能、列表展示、数据上云、≥2 个页面
  • 社交方向：发起功能、参与功能、结果展示、数据上云共享
  • 云数据库至少 1 个集合有真实读写记录
  • 至少 1 个云函数部署到云端
  • 体验版已上传

🎯 最终验收总体目标

三周进度总览

  • 第一次课：环境就绪 + 1 个空页面 + 确定方向
  • 第二次课：核心功能跑通 + 数据进云数据库
  • 第三次课（最终验收）：通用能力补齐 + 体验优化 + 完整交付

🔧 通用技术要求（所有方向都要实现）

⚙️ 通用能力（三个方向统一要求）

以下能力与具体方向无关，是所有小程序都应该具备的基础设施。

必须实现（下课前验收）
  • 用户登录与身份识别：
    • 调用 wx.getUserProfile 或 wx.login 获取用户信息
    • 在云数据库的每条记录中关联用户身份（如 _openid 或昵称）
    • 页面能显示"当前用户是谁"（如首页显示昵称或头像）
  • 云存储使用：
    • 至少 1 处使用云存储（如上传图片、下载文件、存储游戏截图）
    • 云存储的文件能在小程序内正常访问（显示图片/下载文件）
  • 加载状态与错误处理：
    • 数据加载时显示 loading 提示（如"加载中..."）
    • 网络请求失败时有错误提示（如"加载失败，请重试"）
    • 表单提交成功后有成功反馈（如"提交成功"toast）
  • 页面数量 ≥ 3：
    • 在第二次课的 2 个页面基础上，至少新增 1 个页面
    • 新增页面可以是：个人中心、历史记录、设置页、帮助页等
加分项（可选）
  • 有「我的」页面，展示个人数据（如我的记录、我的分数、我的发布）
  • 支持分享给微信好友（wx.shareAppMessage）
  • 有简单的设置功能（如清除缓存、切换主题）

🎮 方向一：轻量小游戏 — 最终验收补充

🎮 方向一：轻量小游戏
在第二次课基础上补充
  • 游戏结束后能保存截图到云存储（可选，但推荐）
  • 有历史最高分记录，显示在首页或游戏结束页
  • 游戏过程中有暂停/继续功能（或至少有"重新开始"按钮）

🧰 方向二：实用工具 — 最终验收补充

🧰 方向二：实用工具
在第二次课基础上补充
  • 支持编辑已有记录（点击记录能修改内容）
  • 支持删除记录（有确认提示，防误删）
  • 列表页支持按条件筛选（如按日期、按分类）

方向三：社交互动 — 最终验收补充

💬 方向三：社交互动
在第二次课基础上补充
  • 支持分享功能（能把互动内容分享到微信聊天）
  • 有参与限制（如每人只能投票一次、不能重复报名）
  • 发起者能查看参与者列表（如谁投了什么、谁报名了）

✅ 最终验收标准（下课前完成）

功能验收（老师扫码或看录屏）

  • 用户登录功能正常（页面能显示当前用户信息）
  • 云存储有使用（至少 1 处上传/下载文件）
  • 加载状态和错误提示完整（不出现"卡死"或"无反馈"）
  • 页面数量 ≥ 3，能正常跳转
  • 前两次课未完成者：第二次课核心功能已补齐

代码验收（检查 GitHub）

  • 云函数代码结构清晰，有注释说明功能
  • 云数据库集合设计合理（字段命名规范）
  • 云存储使用逻辑完整（上传→获取 URL→显示）
  • GitHub 提交记录有本周新 commit

📤 提交要求

下课前提交以下内容

  • GitHub 仓库链接（代码已 push，含本周新提交）
  • 功能演示录屏（30-60 秒，展示本次课新增功能）
  • 体验版二维码截图（老师添加为体验成员后可扫码验证）
  • 前两次课完成情况说明（如"第一次课已完成，第二次课 XX 功能本周补齐"）

📊 最终评分标准（课程总分 100%）

三周成绩构成

  • 第一次课（20%）：环境搭建 + 项目初始化
  • 第二次课（30%）：核心功能跑通 + 云数据库上线
  • 第三次课（50%）：通用能力补齐 + 体验优化 + 完整交付

第三次课（最终验收）评分细则

  • 通用能力实现（40%）：用户登录、云存储、错误处理、页面数量
  • 方向特定补充（25%）：游戏/工具/社交的最终验收补充要求
  • 前两次课补齐（20%）：之前未完成的功能是否在本次补齐
  • 代码质量（10%）：结构清晰、命名规范、Git 提交记录完整
  • 体验版上传（5%）：是否成功上传体验版
